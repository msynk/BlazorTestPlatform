# Changelog

## Unreleased

### Test hub, run history and triage

Informed by a survey of story tools, reporting and analytics platforms, flaky-test and selection tools, visual and accessibility services, cloud grids and the .NET ecosystem (`reports/Modern test platform capabilities.md`).

* **`BlazorTestPlatform.Hub`** (new package): a self-hosted test platform website at `/_btp` over a project's results and run history. Dashboard with pass-rate and duration trends; runs, run detail and run comparison (new failures, still failing, fixed, new flaky, slower); all tests with a story × cell matrix; a result page with failure category, likely cause and next step, timeline waterfall, attempts, artifacts and "copy as prompt"; unique errors; flaky tests and quarantine; visual review with side-by-side, slider, overlay, strobe and diff views, decisions on groups of identical changes and keyboard review; accessibility with new, existing and fixed violations, a needs-review queue and waivers; performance budgets and trends; story-state coverage and a WCAG 2.2 traceability matrix; impact analysis with reasons and duration-balanced shards; in-memory runs started from the browser with live progress; a release-readiness verdict; JUnit, SARIF, Markdown and CSV exports and a JSON API. Off in `Production` unless enabled, with an optional authorization policy, antiforgery-protected actions and files served only from the results and snapshot directories. See [docs/hub.md](docs/hub.md).
* **Run archive**: `btp report --archive <dir>` (and runs started from the hub) record each run with its commit, branch, author, pull request and CI link (GitHub Actions, Azure Pipelines, GitLab, else git) and a compact copy of every result (`RunArchive`, `RunRecord`, `RunInfo.Detect`).
* **Stability and smart tags**: `RunHistory` classifies every result key as new, healthy, failing, flaky, broken or fixed, with a flake rate and its 95% Wilson interval, Cypress-style severity bands, flips and time lost, and tags the latest run (new test, new failure, still failing, always failing, fixed, flaky, slower, quarantined). It also groups failures into clusters, compares runs and tells new accessibility violations from known debt and fixes.
* **Failure analysis**: `FailureAnalysis` gives every failure a stable signature (numbers, durations, GUIDs, paths, URLs and long quoted values normalized) and a deterministic category (assertion, locator, visual, accessibility, performance, render mode, component crash, page error, timeout, infrastructure) with a likely cause and a next step, and builds a self-contained prompt for an assistant or an issue. No model is involved.
* **Quarantine**: a committed `quarantine.json` (patterns over story ids and result keys, with a reason, owner, issue and optional expiry). Quarantined failures are still run and reported, but `VerifyAsync`, the xUnit, NUnit, MSTest and TUnit packages, `RunSummary` and the JUnit report (as skipped) no longer fail the build on them. `btp quarantine add|remove|list` manages it; `BtpSettings.Quarantine` loads it.
* **Visual diff fingerprints**: comparisons record the shape of a change (`VisualResult.DiffFingerprint`) and where it is (`DiffBounds`), so identical changes across stories, themes and browsers can be reviewed as one.
* **Duration-balanced sharding**: `ShardPlan.Create(keys, durations, shards)` assigns work longest first from measured durations, next to the stable hash split of `Shard`.
* **Demo**: the host's home page tours the whole platform (author, run, review, analyze, ship) and hosts the hub; on first start it records ten real in-memory runs, including `Demo/Chaos` stories that fail on purpose in some runs, so the hub has flaky, broken, regressed, fixed and accessibility changes to show.

### Demo overhaul

* **Guided tour**: the demo host's home page (`dotnet run --project demo/BlazorTestPlatform.Demo.Workbench`) explains what the platform does and opens the workbench at the story behind each feature, with its play script running where that helps. [demo/README.md](demo/README.md) maps every feature to its story, code and test; every story has a description that the workbench shows.
* **New showcase components and stories**: pairwise variants with a constraint (`Display/Badge`), focus management, Escape and an accessibility tree snapshot (`Overlays/Dialog`), a form that posts to a mocked API with a delayed response on fake time, a 409 and a network failure (`Patterns/Sign-up form`), computed args from `FakeData`, Razor templates, a cascading-value decorator and render and browser budgets on a long list (`Data/Person list`), a visual mask for a value that differs per render mode (`Display/Runtime badge`), a composition story (`Overview/Kitchen sink`), and an accessibility rule waived with a justification.
* **New demo tests**: `CombinatoricsTests` (the badge variants cover every pair; a pairwise data-driven test of sign-up input), `ImpactAnalysisTests` and `TourTests`. Variant matrices (`visual-matrix`) are now compared once per state, in Chromium on desktop/light, instead of sampling the primary button across themes, viewports and browsers.
* **bUnit driver**: an action no longer waits for an async event handler that is still running after 1 s. A handler that awaited the story's fake clock (a delayed `MockHttp` response triggered by a click) deadlocked the play script, which then also ignored the story timeout. Browsers never wait for handlers either; a handler that fails later is still reported as an unhandled component error.

### Fixes from the review of the second pass

* **CSS cascade in bUnit**: escaped quotes and braces in selectors (Tailwind's `.content-\[\'\'\]`) no longer split cascade layers at the wrong place and drop the rules after them.
* **Browser runs**: a timed-out attempt is stopped before its result is decided: its page is closed (also when it was still opening), it cannot write a baseline or artifacts afterwards, and failure diagnostics are collected from the page as it hung.
* **Test impact analysis**: baselines stored as `{story-id}/{viewport}.{theme}.{browser}-{platform}.png` map to their story; generic components rendered with inferred type arguments (through Razor's generated `TypeInference` helpers) count as dependencies of the components that render them.
* **Workbench services**: a story service that depends on the type it is registered as (a decorator) receives the application's service instead of recursing until the stack overflows; a disposable singleton the application creates with a factory is flagged when the factory's declared type is disposable, and otherwise fails with an explanation instead of being disposed by the first frame; application services that take a service only stories register in their constructor fail with "Unable to resolve service" (or use another constructor) outside those stories instead of receiving null.
* **Results directory safety**: `btp clean` and `ResultsStore.Clear()` look for project files and repositories at any depth, so a results path one level too high (a folder of projects) is refused.
* **bUnit runs**: performance baselines are kept per viewport, theme and args (`btp perf approve` records each configuration under its own key, and pruning keeps every configuration of a live story); results record their viewport, theme and args, so reports tell the configurations apart; a click on a button, link or label inside a `<summary>` no longer toggles the details; focus, hover and `@ref` targets among same-key siblings with repeated text stay on their element when positions shift.
* **Accessibility rules**: `presentation-role-conflict` no longer reports hidden elements (`<svg role="presentation" aria-hidden="true">`), as axe-core; an author `[hidden] { display: none !important }` beats an inline display on an element with the `hidden` attribute.
* **`btp init`**: the generated pipelines run `dotnet test --project <dir>` only when the repository's global.json selects Microsoft.Testing.Platform, and `dotnet test <dir>` in the default VSTest mode.

### New capabilities and fidelity (second pass; see [docs/improvement-progress.md](docs/improvement-progress.md))

* **Test framework packages**: `BlazorTestPlatform.Xunit`, `.NUnit`, `.MSTest` and `.TUnit` turn catalogs, stories and matrix cells into native data rows (`StoryTheoryData`, `StoryTestCases`, `StoryDataRows`) named after the story, with tags as categories and `.Skip(...)` reasons applied at discovery, and `Passed(result)` reports a skipped run as the framework's skip instead of a pass. `StoryTestCase.From(...)` is the framework-neutral form. See [test frameworks](docs/test-frameworks.md).
* **`btp init`** scaffolds `btp.json`, a story test class for xUnit, NUnit, MSTest or TUnit, a first story for a component, and a GitHub Actions, Azure Pipelines or GitLab pipeline on the matching Playwright image.
* **Browser emulation**: `Geolocation(...)`, `GrantPermissions(...)`, `NetworkLatency(...)` (or `Emulate(e => e with { ... })`) on stories, and `ctx.SetGeolocationAsync(...)` / `ctx.SetOfflineAsync()` in play, in Chromium, Firefox and WebKit. A new capability, `DriverCapabilities.BrowserEmulation`, makes bUnit and the in-app driver skip such stories with the reason; `InAppStoryDriver.CapabilitiesFor(story)` joins the bUnit and Playwright equivalents.
* **Browser runtime metrics**: every real-browser result carries `BrowserMetrics` (cumulative layout shift, largest contentful paint, long tasks, story DOM size, JS heap), and `BrowserBudget(b => ...)` fails a run that exceeds a limit. Limits on metrics a browser does not report are listed as not checked, never passed silently.
* **Accessibility tree snapshots**: `ctx.ExpectAriaSnapshotAsync("""...""")` and `ctx.GetAriaSnapshotAsync()` compare roles, names and states as an indented tree, computed by `AriaSnapshot` in bUnit and by its port in the browser drivers, so a snapshot passes or fails alike everywhere (`IStoryDriver.GetAriaSnapshotAsync` has a default implementation for custom drivers).
* **Workbench inspector and recorder**: under the frame of an interactive story, live actions, mocked requests, JS-interop calls, console messages and the accessibility tree; **Record** writes a play function from what you do in the frame, with the most readable unique locator for each element.
* **Test impact analysis**: `StoryImpact.Analyze(catalog, changedFiles)` maps changed files to the stories they can affect (story files, component files and the components that render them, files that carry a story id) and runs everything when a change cannot be placed; `StoryImpact.FromEnvironment(catalog)` uses `BTP_CHANGED_SINCE=origin/main`; `StoryImpact.ChangedFilesSince(ref)` includes uncommitted and untracked files.
* **SARIF**: `btp report --sarif <file> [--source-root <dir>]` writes SARIF 2.1.0 (accessibility violations, failed stories, visual and performance regressions) located at the line that declares each story's collection, with stable fingerprints, for GitHub code scanning and other SARIF viewers.
* **OpenTelemetry**: `BtpTelemetry` traces every story run (`btp.story`, with a `btp.step` child per timeline step) and records `btp.story.runs` and `btp.story.duration` on the `BlazorTestPlatform` meter, in bUnit and browser runs; nothing is collected unless a listener subscribes.
* **Story source locations**: `Story.SourceFile`/`SourceLine` (and the same on results), recorded by the source generator for every collection.
* **Code fixes** for the story analyzers, shipped in the Core package: add `[Parameter]` to the selected property (BTP001), turn a binding without a `Changed` callback into `Arg` (BTP002), turn `Attribute("Name", value)` into `Arg(c => c.Name, value)` (BTP003), rename a duplicate story to the next free name (BTP005). BTP005 no longer reports stories added in exclusive branches (`if`/`else`, `switch`).
* **Flake history**: entries count flips (failing then passing, or the reverse) and rank equal rates by them; `btp flaky` prints them.
* **Workbench services**: story registrations can depend on application services under Server and WebAssembly, as in bUnit; keyed registrations and open generics the application does not register are flagged as not applying in browsers; overrides are probed under every render mode; manual reviews are cached by file time; a story host disposed during play cancels it and releases the imported module.
* **HTTP and JS mocks**: named clients keep their `AddHttpClient` base address, headers and delegating handlers (only the primary handler is mocked); `MockJS` mocks `GetValueAsync`, `SetValueAsync` and `InvokeConstructorAsync` (`SetupGet`, `SetupSet`, `"new X"`), in-process references included, and a missing mocked module imported in-process returns a working reference.
* **bUnit fidelity**: focus, hover and `@ref` targets follow the element across re-renders (inserting a sibling before the focused element keeps focus); arrow keys move within radio groups; `<summary>` toggles its `<details>` and fires `toggle`; Enter inserts a line break in textareas and contenteditable; the `buttons` bitmask follows the pressed button; `preventDefault` on checkbox and radio clicks reverts the toggle; drops need a `dragover` handler that prevents the default (otherwise `dragleave`); Tab continues from the last click; `FillAsync` waits while a field is `readonly`. The in-app driver follows the same rules, and `change` fires only when a value really changed.
* **CSS cascade in bUnit**: cascade layers (`@layer` statements, blocks, nested and anonymous layers, with the reversed order for `!important`), `@container` queries, per-selector specificity in selector lists, `inherit`/`initial`/`unset`/`revert` keywords, author `display` overriding `hidden`, and bare boolean media features such as `(prefers-reduced-motion)`. A configured stylesheet that does not exist fails instead of being ignored.
* **Accessible names and roles (both engines)**: a control inside an `aria-labelledby` target contributes its value; a wrapping label names only its first labelable descendant; `title=""` no longer hides the placeholder; text in table cells and other block elements is separated by spaces in names from content (a row of "Plan" and "Team" is "Plan Team", as in browsers); `input type=file` is a button; the global ARIA attribute list is complete (ARIA 1.2); the `aria-level` exemption applies to `h1`-`h6` only.
* **Visual**: translucent pixels are compared after compositing (alpha-only changes are no longer invisible), and a baseline written by an attempt that fails another check is reverted instead of becoming the reference.
* **Hosts and packaging**: a process host retries startup on "address already in use"; the Core package finds the generator and code-fix assemblies wherever they were built (`-o`, `--artifacts-path`).

**Behaviour changes to check when upgrading (second pass):**

* Story option objects (`Visual`, `Accessibility`, `Performance`, `BrowserBudget`) are read-only once a story is built; setting one throws. Configure them in the story builder or pass run options.
* Tests that used `TheoryData<string>(Catalog.Ids)` with `VerifyAsync` keep working, but skipped runs still pass there; the framework packages report them as skipped.
* Accessible names computed from content now separate text of block-level and table-cell elements with spaces, in bUnit and the browser drivers: a name assertion on such an element may need the space (`"Plan Team"`).
* `IStoryBuilder` gained default-implemented members (`Emulate`, `BrowserBudget`) and `IStoryDriver` gained `GetAriaSnapshotAsync`, `SetOfflineAsync` and `SetGeolocationAsync` with defaults that throw `NotSupportedException`: custom implementations compile unchanged.
* The sample's in-app test cases leave out stories the in-app driver cannot run (`InAppStoryDriver.CapabilitiesFor`).

### Hardening and new capabilities (audit of every package; see [docs/improvement-progress.md](docs/improvement-progress.md))

* **Capability requirements on stories**: `Requires(DriverCapabilities.Layout, "why")` declares what a story needs. The bUnit, browser and in-app runners skip it up front, with the reason, on drivers that lack the capability, instead of rendering and failing (or skipping) mid-play. `StoryCatalog.Supporting(capabilities)`, `Story.CanRunOn` and `Story.UnsupportedReason` let test data sources leave such stories out, and `BunitStoryDriver.CapabilitiesFor(story)` / `PlaywrightStoryDriver.CapabilitiesFor(mode, fakeTime)` report a driver's capabilities without starting it. [Interactions](docs/interactions.md#driver-capabilities) has the per-driver capability table.
* **Pairwise variants**: `AddVariants(v => v.Vary(...).Vary(...).Pairwise())` covers every pair of parameter values instead of every combination (deterministic In-Parameter-Order selection), and `.Where(...)` leaves out unsupported combinations. `Combinatorics.Pairwise`, `CartesianProduct` and `MissingPairs` are public for data-driven tests.
* **Sharding**: `Shard.FromEnvironment()` (`BTP_SHARD=2/4`), `cases.InShard(shard)` and `catalog.InShard(shard)` split a matrix across CI jobs with a stable, hash-based assignment.
* **Workbench security**: the workbench is **off in the `Production` environment** unless `WorkbenchOptions.Enabled = true` (or `BTP_WORKBENCH_ENABLED=true`); disabled pages answer 404. `WorkbenchOptions.AuthorizationPolicy` restricts who may open it. Links can no longer pass `javascript:`, `vbscript:` or `data:` URLs as arguments (`StoryArgs.IsScriptUrl`), and play results are posted to, and accepted from, the workbench's own origin and frame only.
* **Versioned results**: result files carry `schemaVersion`; readers report files from a newer version, and files that cannot be parsed, instead of dropping them silently. `ResultsStore.ReadAll(out unreadable)` lists them, and `btp report --fail-on-failures` fails when any exist.
* **Reliable browser runs**: the per-attempt timeout now bounds navigation, axe, captures and diagnostics (a story that blocks the browser fails as timed out instead of hanging the run); caller cancellation stops retries and is no longer reported as a timeout; a crashed browser is relaunched; failure diagnostics are bounded; errors caught by the story's error boundary after hydration fail the run; early console errors can no longer be evicted by later logging; offscreen lazy images no longer stall snapshots; `dotnet run` hosts are stopped when startup fails.
* **Reliable bUnit runs**: an exception a component throws after an `await` (outside any error boundary) fails the story instead of letting it pass; stories without a play function settle before markup rules run; caller cancellation is no longer reported as a timeout; runs with a different viewport, theme or args get their own result key; allocation calibration no longer depends on which story ran first; medians use the middle pair for even sample counts; `MeasureAsync` measures with the run's viewport, theme and stylesheets.
* **bUnit fidelity**: text typed into, and the checked state of, controls the component does not bind now survive re-renders (as in a browser, until the component renders a new value); Enter fires `keypress` (also in the in-app driver); checking a radio unchecks the rest of its group.
* **Accessibility rules aligned with axe-core**: empty id references, `aria-controls` of collapsed or unselected owners, `aria-owns` of collapsed comboboxes, missing `aria-labelledby`/`aria-describedby` targets and hidden elements no longer fail `aria-valid-attr-value`; empty lists, listboxes, menus, tablists, trees and grids no longer fail `aria-required-children`; `nested-interactive` checks only roles with presentational children (APG trees and links with focusable content pass); `aria-dialog-name` checks explicit dialog roles only; `summary-name` uses the accessible name.
* **Visual**: every render mode and attempt keeps its own actual/diff images, so a later match or a passing retry no longer deletes the evidence of a mismatch; baselines are written atomically; snapshot names cannot leave the baseline directory; the PNG decoder verifies CRCs, header length, bit-depth/colour-type combinations and dimensions, and inflates only the announced data.
* **CLI and reports**: `btp clean` (and `ResultsStore.Clear`) refuses to delete directories that hold sources, a repository or the current directory, and an empty `BTP_RESULTS_DIR` no longer resolves to the project directory; `btp approve` writes only into the project's snapshot directory, copies only PNGs from the results directory it read, works on results downloaded from CI, and keeps going past snapshots it cannot approve; JUnit output survives control characters and ANSI colours; Markdown summaries escape table pipes in result keys, code spans and `@mentions`; the pull-request comment is found only in comments a bot (or `BTP_PR_COMMENT_AUTHOR`) posted; a corrupt flake history is reset with a warning; history files are written atomically; non-HTTP errors while commenting no longer fail the report; help links in the HTML report must be http(s); `btp` rolls forward to newer runtimes.
* **Settings**: CI is detected on Jenkins, AWS CodeBuild, CircleCI, Bitbucket, AppVeyor, Travis, Drone, Semaphore and Bitrise, and when `CI` holds a system name; `BTP_CI` overrides detection. `BTP_TIMEOUT_MS` must be positive.
* **Assertions**: negated single-element assertions (`Not.ToBeDisabledAsync()`, `Not.ToBeCheckedAsync()`, `Not.ToContainTextAsync(...)`...) fail on a missing or ambiguous element instead of passing; `ToBeVisibleAsync`/`ToBeHiddenAsync` are strict about multiple matches; `times: 0` waits for the story to settle; JS-call arguments format collections, dictionaries and objects by content; `Poll` accepts `Timeout.InfiniteTimeSpan`; `Keys.Chord(Keys.Shift, "+")` parses and `ControlOrMeta` is Control outside macOS.
* **Test data**: removing a live override of a parameter whose default is unknown recreates the component instead of passing null; `HttpMock.ClearRequests()` during an in-flight request no longer throws, and sequence numbers never repeat; relative URLs resolve against the directory of a `BaseAddress` without a trailing slash, as `HttpClient` does; mock clients have no real-time timeout; JS-mock module setups from collection defaults and the story accumulate; enum aliases are one state in controls and coverage; `TimeOnly` args keep sub-second precision; `NextDecimal` stays in range for negative ranges; matrices deduplicate repeated dimensions; manual reviews without a fingerprint are stale and reviews without checks incomplete; story-scoped suppressions no longer apply when no story id is given; the performance baseline store is safe for parallel writers in one or several processes.
* **Workbench services**: overrides of services the application registers as disposable singletons are flagged instead of having the frame scope dispose the shared instance; the application's options monitor is no longer disposed by frame scopes; a service only stories register stays optional (`GetService<T>()` returns null) outside them.
* **Generator and packages**: record story configurations are discovered; assembly names that start with a digit generate a valid namespace; types with required members are created through `Activator`; file-local and error-obsolete types are skipped by both the generator and reflection discovery. Packages that reference Core (Bunit, Playwright, Workbench, Accessibility, Visual, Reporting) now pass its generator and analyzers on to their consumers.

**Behaviour changes to check when upgrading:**

* Workbench hosts that run in `Production` (preview deployments, a trimmed CI publish) must set `WorkbenchOptions.Enabled = true` or `BTP_WORKBENCH_ENABLED=true`.
* Play scripts that relied on a negated state assertion passing for a missing element, or on `ToBeVisibleAsync` accepting several matches, now fail: narrow the locator (`.First`, `.Nth(i)`, a name) or assert `ToHaveCountAsync`.
* `VariantBuilder.Vary` rejects a parameter that is already varied in the same `AddVariants` call.
* Results of bUnit runs with a non-default viewport, theme or args are written under a longer key (`story|bunit|mobile`), so they no longer overwrite the default run's result.
* JS-call arguments that are collections, dictionaries or objects are compared by content (`[1, 2]`, JSON) rather than `ToString()`; assertions comparing against a type name must use the value.
* Visual actual/diff images are named per render mode and attempt (`desktop.light.chromium-linux.wasm-attempt-1.actual.png`).

* **Live controls in the workbench**: a Controls panel generated from the component's parameter types (text, checkbox, number, drop-down, date and time inputs, with nullable variants). Interactive frames re-render in place through `window.__btp.setArgs`, two-way bindings included, and static frames reload. Edits are kept in the URL (`?arg.Name=value`) so links reproduce them. Values from links can't contain `<`. The same overrides are available to tests through `BunitStoryOptions.Args`, `StoryPageOptions.Args` and `StoryRenderContext.SetArgOverridesAsync`, and the rules are exposed by `StoryArgs`.
* **Story analyzers** in the Core package: `BTP001` (argument isn't a component parameter), `BTP002` (binding without a matching `Changed` callback), `BTP003` (`Attribute` used for a declared parameter), `BTP004` (component can't take unmatched attributes) and `BTP005` (duplicate story id). Each one reports at compile time a mistake that used to fail when the catalog was built or the story rendered.
* **Story state coverage**: `StoryCoverage.Analyze(catalog, StoryCoverage.ComponentsIn(assembly))` lists, for every `bool` and enum parameter, the values no story renders, and the components that have no stories. `ThrowIfBelow` makes it a gate. The report is saved next to the results (`story-coverage.json`), and `btp report` adds it to the HTML report and the Markdown summary. The workbench shows each component's covered and missing states.
* **Pull-request comments**: `btp report --pr-comment` posts the Markdown summary on the GitHub pull request and updates the same comment on later runs. A read-only token (pull requests from forks) only produces a warning. The summary now links to the workflow run (`--report-url` overrides it).
* **Firefox and WebKit baselines**: the sample's `CrossBrowserTests` run every story's play script, snapshot and axe scan in Firefox and WebKit, and CI gates on `firefox-linux` and `webkit-linux` baselines rendered in the same Playwright container as Chromium's. The scripts and the **Regenerate visual baselines** workflow cover them, and `BaselineProvenanceTests` checks every Linux browser.
* **Accessibility waivers in reports**: each run lists the rules it is excused from (`AccessibilityReport.Waivers`): the story's disabled rules with their justifications, rules disabled for every story, and matching active suppressions. The HTML report shows them. A rule disabled through `Accessibility(a => a.DisabledRules...)` without a justification now fails when the catalog is built. `btp.json` accepts `accessibility.includeBestPractices`.
* **Manual reviews**: review templates carry each check's title, WCAG criterion and guidance, and the workbench shows the guidance on hover. The review gate writes `a11y-review-gate.json`, so `btp a11y status` shows `Approved`, `Missing`, `Stale`, `Incomplete` and `Failed` states.
* Failure messages end with the last steps of the timeline. Flaky browser runs keep the artifacts (trace, screenshot, DOM) of their failed attempts.
* `btp approve` records the renderer of approved screenshots in `__snapshots__/baselines.json`, so baselines approved after a Playwright upgrade no longer fail `BaselineProvenanceTests`.
* The CLI honours `BTP_PROJECT_DIR` when `-p` is not given. `BTP_HEADED` and `BTP_INSTALL_BROWSERS` accept `true` and `yes`, like the other flags.
* Locators chain `GetByPlaceholder`, `GetByAltText` and `GetByTitle`, like `StoryContext`.
* **One query engine for the browser drivers**: the Playwright and in-app drivers find elements with one script that ports the in-memory engine: the full implicit-role table (`banner`, `contentinfo`, `rowheader`, `meter`, `search`...), accessible names (`aria-labelledby`, labels, `alt`, `title`, placeholder, name from content without hidden parts) and text with the same block spacing (`<div>A</div><div>B</div>` is `A B` everywhere). Queries are scoped to the story root, so host-page chrome such as `#blazor-error-ui` never matches. Strict-mode errors list the matched elements in every driver, and `By.TestIdAttribute` is read at query time. The Playwright driver still acts through real Playwright input. The in-app driver follows the same keyboard, focus, fieldset and `inert` rules as bUnit, and checks a checkbox with one click instead of possibly two under Server. The sample's `DriverParityTests` compare roles, names, text and state across drivers element by element.
* **bUnit fidelity**: elements in a disabled `<fieldset>` (outside its first `<legend>`) are disabled and skipped by Tab, `inert` subtrees can't be focused or acted on, and only the first `<summary>` of a `<details>` is focusable. Enter never toggles checkboxes or radios; it activates buttons and links and performs HTML implicit submission (default button, single-field forms). Space never activates links. `ElementReference.FocusAsync()` calls made by components fire blur, focusout, focus and focusin (and change-on-blur), as in a browser. Accessibility report targets of the markup rules are anchored at `body >`, so they always resolve to the element they name.
* Fixes:
  * `.Not.ToHaveCountAsync(n)` failed whenever the number of matches wasn't exactly 1.
  * `?play=1` on a static SSR frame never reported a result, so `WaitForInAppPlayAsync` timed out after 60 s. Static frames now report `skipped`.
  * `WorkbenchBrowser.OpenAsync` ignored a story's `.Prerender(false)`.
  * The in-app driver ignored the story's `.Timeout(...)`.
  * The flake history on this repository's CI was only saved when every test passed.
  * The container scripts kept using a cached .NET SDK older than `global.json` requires.
  * This repository committed the Windows (`*-win32`) baselines written by local runs. Only the Linux baselines CI gates on are committed now, `.gitignore` keeps the others out, and [What to commit](docs/configuration.md#what-to-commit) covers per-platform baselines.
* **Fake data change** (snapshots that show generated data may change): `FakeData.Email()` uses `mail.example` instead of `test.dev`, which is a real, registrable domain, and `FakeData.Phone()` returns numbers in the 555-0100 to 555-0199 block reserved for fiction (`+1-415-555-0142`) instead of `+1-555-…`. The `DeterministicRandom` sequence is unchanged, so every other generated value stays the same.

## 0.1.0-preview.2

* **Story-scoped HTTP mocking**: `MockHttp(...)` answers requests from `HttpClient` and from named or typed `IHttpClientFactory` clients in bUnit, Interactive Server and WebAssembly. It supports wildcards, `Times`, `Delay` (on fake time), `Never`, `Fail` and request recording. Assert with `ctx.ExpectRequest(...)`; requests appear in the HTML report.
* **Run interactions in the workbench**: a third driver (`InAppStoryDriver`) runs play scripts inside the frame under the real render mode, using native activation, focus and `preventDefault`. The shell shows the live timeline. `StoryPageOptions.AutoPlay` runs it from tests.
* **Source-generated story discovery**: `BlazorTestPlatform.Generators` ships inside the Core package. Core and Workbench are trimming-safe, with zero trim warnings and source-generated JSON throughout. The suites run against a trimmed Release publish on CI.
* **bUnit fidelity**: stylesheet-aware visibility (a cascade for `display`/`visibility`, including CSS-isolation bundles) via `bunit.stylesheets` or `BunitStoryOptions.Stylesheets`. `@media` queries are evaluated against a viewport (`BunitStoryOptions.Viewport`, `bunit.viewport`, `BTP_BUNIT_VIEWPORT`; desktop by default, as in browser runs) and the theme's color scheme (`BunitStoryOptions.Theme`): width, height and range syntax, orientation, `prefers-color-scheme`, `prefers-reduced-motion`, `hover`, `pointer`, nested `@media` and `@supports`.
* **JS-interop mocks everywhere**: `MockJS(...)` answers in bUnit and, with `ApplyInBrowsers()`, in workbench frames under Server, WebAssembly and Auto. Unmocked calls reach the real JavaScript (or fail in strict mode), and Blazor's own calls are never touched. Stories with mocks record their JS calls under every driver: `ctx.ExpectJSCall(...)` and `ctx.GetJSCallsAsync()`.
* **Per-story overrides of multi-registration services in browsers**: story registrations are composed with the application's (`IEnumerable<T>` yields both, `T` yields the story's), so options (`IOptions<T>`, `IOptionsSnapshot<T>`, `IOptionsMonitor<T>` per story), authorization handlers and your own multi-registered services work under every render mode. Contracts consumed at start-up (hosted services, logger providers, startup filters, circuit handlers, handler-builder filters) are flagged on the story in the shell, the frame and the run timeline instead of being ignored silently.
* **Linux baselines**: `scripts/visual-tests.sh` / `.ps1` run the browser suites in the Playwright image used by CI, so CI gates on `chromium-linux` baselines. The image tag is derived from the pinned `Microsoft.Playwright` version in the scripts and the workflow.
* **Painless Playwright upgrades**: `__snapshots__/baselines.json` records the renderer behind each `{browser}-{platform}` baseline set. After an upgrade, `BaselineProvenanceTests` fail fast, visual mismatches explain that the browser changed, and the **Regenerate visual baselines** workflow commits the new baselines to the branch. Dependabot is configured for `Microsoft.Playwright`.
